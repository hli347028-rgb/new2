# 前端积分接口文档

本文档对应当前后端实现，供用户端前端展示 **当前积分**、**总积分**、**获得积分时间**。

## 1. 通用约定

- 生产环境可使用相对路径（与站点同域），例如 `/v1/wallet/...`
- 请求头：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

- 金额 / 积分字段均为**字符串**，避免 JS 浮点误差，例如 `"100"`、`"100.5"`
- 时间字段：
  - `created_at` / `created_time`：Unix 秒时间戳（number）
  - 前端展示请按本地时区格式化

## 2. 业务规则（积分来源）

- 用户每认购一笔订单，获得积分数 = **该笔认购金额（principal）**
- `points`：当前积分余额  
- `points_all`：累计总积分（历史认购获得的积分之和）  
- 当前版本积分仅由认购产生，暂无消耗；因此一般 `points == points_all`
- 获得时间 = 对应认购订单的创建时间

---

## 3. 资产总览（含积分 / 总积分）

### 接口

```http
GET /v1/wallet/aix-profile
```

### 响应（积分相关字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| points | string | 当前积分 |
| points_all | string | 累计总积分 |
| … | … | 其它原有资产字段不变 |

### 响应示例（节选）

```json
{
  "address": "0xabc...",
  "usdt_recharge": "1000",
  "usdt_reward": "50",
  "aix_balance": "10",
  "win_balance": "20",
  "overflow_reward": "0",
  "points": "300",
  "points_all": "300",
  "static_usdt_total": "12.5",
  "win_price": 3.23
}
```

### 前端用法建议

- 首页 / 资产页展示：`points`、`points_all`
- 进入积分明细页再调下一节接口

## 4. 积分获取记录（含获得时间）

### 接口

```http
GET /v1/wallet/points-records
```

### 响应

| 字段 | 类型 | 说明 |
|------|------|------|
| points | string | 当前积分 |
| points_all | string | 累计总积分 |
| count | number | 记录条数 |
| records | array | 积分获取明细，按订单列表返回（通常新单在前，取决于后端排序） |

#### records[] 元素

| 字段 | 类型 | 说明 |
|------|------|------|
| id | number | 记录 ID（等于订单 ID） |
| order_id | number | 认购订单 ID |
| points | string | 本笔获得积分（= 认购金额） |
| principal | string | 认购本金（USDT） |
| fund_source | string | 资金来源：`recharge` / `reward` / `win` |
| status | string | 订单状态：`active` / `exited` 等 |
| created_at | number | 获得积分时间（Unix 秒） |
| created_time | number | 同 `created_at`（兼容字段） |

### 响应示例

```json
{
  "points": "300",
  "points_all": "300",
  "count": 2,
  "records": [
    {
      "id": 12,
      "order_id": 12,
      "points": "200",
      "principal": "200",
      "fund_source": "recharge",
      "status": "active",
      "created_at": 1723708800,
      "created_time": 1723708800
    },
    {
      "id": 8,
      "order_id": 8,
      "points": "100",
      "principal": "100",
      "fund_source": "win",
      "status": "exited",
      "created_at": 1723622400,
      "created_time": 1723622400
    }
  ]
}
```

### 前端展示建议

| UI | 字段 |
|----|------|
| 当前积分 | `points` |
| 总积分 | `points_all` |
| 明细行：积分数 | `records[i].points` |
| 明细行：获得时间 | `new Date(records[i].created_at * 1000)` |
| 明细行：关联订单 | `records[i].order_id`（可选） |

## 5. 认购成功返回（即时刷新积分）

认购接口成功后也会带回本单积分与最新累计，便于前端立刻刷新，无需再请求一次 profile。

### 接口

```http
POST /v1/wallet/subscribe-aix
```

### 请求（原有）

```json
{
  "amount": "100",
  "pay_from": "recharge"
}
```

`pay_from`：`recharge` | `reward` | `win`

### 响应（新增积分字段）

| 字段 | 类型 | 说明 |
|------|------|------|
| points | string | 本单获得积分（= amount / principal） |
| points_balance | string | 认购后当前积分 |
| points_all | string | 认购后累计总积分 |
| order_id / principal / … | … | 原有字段不变 |

### 响应示例（节选）

```json
{
  "order_id": 15,
  "principal": "100",
  "exit_cap": "400",
  "fund_source": "recharge",
  "status": "active",
  "points": "100",
  "points_balance": "400",
  "points_all": "400"
}
```

---

## 6. 调用流程示意

```text
登录拿到 token
    │
    ├─ GET /v1/wallet/aix-profile     → 展示 points / points_all
    │
    ├─ GET /v1/wallet/points-records  → 展示明细 + 获得时间
    │
    └─ POST /v1/wallet/subscribe-aix  → 认购成功后用返回值刷新积分
```

---

## 7. 错误与鉴权

- 未登录 / token 无效：与其它 `/v1/wallet/*` 一致（通常 401）
- 积分记录为空时：`records: []`，`count: 0`，`points` / `points_all` 仍为 `"0"` 或当前值

## 8. 备注

- 积分明细当前由认购订单派生，不另建流水表；`created_at` 即认购时间
- 若后续增加积分消耗，将扩展新接口与流水类型，本文档会同步更新
