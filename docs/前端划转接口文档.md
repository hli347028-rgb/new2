# 前端划转接口文档

本文档对应当前后端实现，供用户端前端调用。

## 1. 通用约定

- 局域网基础地址：`http://192.168.3.6:8081`
- Radmin VPN 基础地址：`http://26.3.54.166:8081`
- 请求格式：`application/json`
- 金额字段统一使用字符串，避免 JavaScript 浮点精度问题，例如：`"100.5"`
- 所有接口均需要登录令牌：

```http
Authorization: Bearer <token>
Content-Type: application/json
```

前端与 API 同域部署时，推荐只请求相对路径，如 `/v1/wallet/transfer`。

## 2. 用户之间奖励钱包划转

### 接口

```http
POST /v1/wallet/transfer
```

### 业务规则

- 只支持 `USDT`。
- 只能从转出用户的奖励钱包扣款，`pay_from` 必须为 `reward`。
- 收款金额进入收款用户的奖励钱包。
- 仅允许邀请树中的直系上下级互转，支持跨层级祖先/后代关系。
- 同一邀请树中的不同分支用户不能互转。
- 不能转给自己。
- 收款地址必须是系统内已注册用户的钱包地址。
- 此接口是系统内部账本划转，不发送区块链交易，不需要钱包签名或 Gas。
- 扣款、入账和转账记录在同一个数据库事务中完成。

### 请求参数

| 字段 | 类型 | 必填 | 固定值/说明 |
| --- | --- | --- | --- |
| `to_address` | string | 是 | 收款用户的钱包地址 |
| `asset` | string | 是 | 固定传 `USDT` |
| `amount` | string | 是 | 大于 0 的划转金额 |
| `pay_from` | string | 是 | 固定传 `reward` |

### 请求示例

```json
{
  "to_address": "0x9e3730f324476c15b9cf1b1991e0c2cc5c8d1575",
  "asset": "USDT",
  "amount": "100",
  "pay_from": "reward"
}
```

### 成功响应

HTTP 状态码：`200`

```json
{
  "id": 123,
  "from_user_id": 10,
  "to_user_id": 11,
  "asset": "USDT",
  "amount": "100",
  "pay_from": "reward",
  "to_credit_reward": "100",
  "to_credit_aix": "0"
}
```

### Axios 调用示例

```ts
import axios from 'axios'

export interface RewardTransferRequest {
  to_address: string
  amount: string
}

export interface RewardTransferResult {
  id: number
  from_user_id: number
  to_user_id: number
  asset: 'USDT'
  amount: string
  pay_from: 'reward'
  to_credit_reward: string
  to_credit_aix: string
}

export async function transferReward(
  token: string,
  input: RewardTransferRequest,
): Promise<RewardTransferResult> {
  const { data } = await axios.post<RewardTransferResult>(
    '/v1/wallet/transfer',
    {
      to_address: input.to_address,
      asset: 'USDT',
      amount: input.amount,
      pay_from: 'reward',
    },
    {
      headers: { Authorization: `Bearer ${token}` },
    },
  )
  return data
}
```

## 3. 本人充值钱包划转到奖励钱包

### 接口

```http
POST /v1/wallet/recharge-to-reward
```

### 业务规则

- 只在当前登录用户自己的两个钱包之间划转。
- 从充值钱包扣除 USDT，等额增加奖励钱包 USDT。
- 金额必须大于 0，且不能超过充值钱包余额。
- 不产生直推奖励。
- 此接口不涉及链上交易。

### 请求参数

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `amount` | string | 是 | 大于 0 的划转金额 |

### 请求示例

```json
{
  "amount": "50"
}
```

### 成功响应

HTTP 状态码：`200`

```json
{
  "usdt_recharge": "950",
  "usdt_reward": "150"
}
```

响应字段为划转完成后的最新余额。

### Axios 调用示例

```ts
export interface RechargeToRewardResult {
  usdt_recharge: string
  usdt_reward: string
}

export async function rechargeToReward(
  token: string,
  amount: string,
): Promise<RechargeToRewardResult> {
  const { data } = await axios.post<RechargeToRewardResult>(
    '/v1/wallet/recharge-to-reward',
    { amount },
    {
      headers: { Authorization: `Bearer ${token}` },
    },
  )
  return data
}
```

## 4. 错误响应

后端错误响应通常为：

```json
{
  "code": 400,
  "reason": "INSUFFICIENT_BALANCE",
  "message": "余额不足"
}
```

前端建议优先显示 `response.data.message`。

### 用户间奖励钱包划转错误

| HTTP 状态 | `reason` | `message`/含义 |
| --- | --- | --- |
| 400 | `INVALID_ADDRESS` | 收款地址无效 |
| 404 | `USER_NOT_FOUND` | 收款用户不存在 |
| 400 | `INVALID_TRANSFER` | 不能转给自己 |
| 400 | `NOT_UPLINE_DOWNLINE` | 仅允许邀请树上下级互转 |
| 400 | `INVALID_ASSET` | 仅支持奖励钱包 USDT |
| 400 | `INVALID_AMOUNT` | 转账金额必须大于 0 |
| 400 | `INVALID_PAY_FROM` | 只能从奖励钱包扣款 |
| 400 | `INSUFFICIENT_BALANCE` | 奖励钱包余额不足 |
| 401 | `UNAUTHORIZED` | 未登录或令牌失效 |

### 充值钱包转奖励钱包错误

| HTTP 状态 | `reason` | `message`/含义 |
| --- | --- | --- |
| 400 | `INVALID_AMOUNT` | 划转金额必须大于 0 |
| 400 | `INSUFFICIENT_BALANCE` | 充值钱包余额不足 |
| 401 | `UNAUTHORIZED` | 未登录或令牌失效 |

### 前端错误处理示例

```ts
try {
  await transferReward(token, {
    to_address: receiver,
    amount,
  })
  showSuccessToast('划转成功')
} catch (error: any) {
  const message = error?.response?.data?.message || error?.message || '划转失败'
  showFailToast(message)
}
```

## 5. 前端交互建议

- 提交前校验地址格式、金额大于 0，并禁止重复点击。
- 请求过程中显示加载状态。
- 成功后重新请求用户资产接口，刷新充值钱包和奖励钱包余额。
- 金额展示和计算使用字符串或高精度库，不要直接使用 JavaScript 浮点运算。
- 用户间划转按钮旁明确注明“仅邀请关系上下级可互转，收款进入奖励钱包”。
